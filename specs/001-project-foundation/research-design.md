## 4. 愿景、三个体验支柱与循环建议

**愿景建议**：让玩家在被异变重新塑形的城市中，依靠自己的准备、路线判断和装备操作建立生存方式；珍爱的早期装备随个人世界成长而获得新的用途。

1. **每次出发有取舍，带回资源有用途。** 出营时看懂目标、危险与补给；探索中至少出现“继续深入或安全撤回”“高价值路线或低风险绕行”的可解释选择；回营的资源直接服务下一次计划。失败要能追溯到判断、操作或准备，不以未知惩罚制造压力。
2. **成长带来新的打法。** 一阶闪电枪让玩家选择起始目标与怪群密度；二阶锚点让玩家先布置再连接分散目标。装备身份、经历与机制取舍贯穿培养，融合随机结果可以变差但规则、概率与成本应清楚。
3. **晋阶改变世界中的可能。** 等级门槛后的挑战检验所学，挑战成功后开放新资源与操作，同时为旧区域赋予回访价值。合作后续评估应带来提前发现的机会，保留单人完整路径与个人晋阶权威。

**短周期**：观察目标/威胁 → 移动、瞄准或布置 → 攻击/防御 → 读懂命中与危险反馈 → 改变站位或决定撤离。
**一次远征**：营地确认目标、路线与补给 → 探索采集 → 遭遇与资源取舍 → 撤离/失败 → 真实结算与保存 → 制作/装备培养 → 下一次计划。
**长期循环**：公共解锁与个人世界经验 → 等级门槛 → 晋阶挑战 → 新区域/材料与装备新动作 → 旧区域的新解法 → 构筑与营地继续发展。

用户给出的10–20分钟普通探索、25–40分钟完整远征、3–10分钟营地整理、首轮20–30小时属于讨论目标。当前没有足够人力、预算、设备或试玩证据，将它们作为承诺会失真；应在切片后以实际行为与生产吞吐确认。

### 首轮系统价值与删除损失

| 系统 | 玩家选择与反馈 | 核心循环作用 | 首轮验证 | 删除后的损失 |
|---|---|---|---|---|
| 路线与有限补给 | 高风险高收益路径、撤离时机；背包/补给状态与危险提示 | 让采集承担代价，营地准备有意义 | 同一目的地至少两种可走方案，记录选择理由与损失 | 远征退化为单向清怪，生存题材只剩外观 |
| 动作战斗 | 首目标、站位、闪避/防御时机；命中、预备、恢复与受击反馈 | 将构筑落实到操作结果 | 稀疏与密集敌人都出现，观察打法是否变化 | 装备成长只剩列表数值 |
| 营地制作/建设 | 用资源建一个有功能的设施或制备补给；显示消耗与产出 | 把资源带回的价值落实为下一次准备 | 成本守恒、存档恢复、设施实际作用 | 回营成为无意义的菜单停顿 |
| 装备进阶/融合/扩槽 | 保留身份、锁词条、承担随机性；预览资格/候选/概率/总成本 | 提供长期培养与资源消耗 | 法律性边界、真实消费、无法填满候选时不暗改规则 | 早期惊喜无法长期培养；反复探索目标变弱 |
| 世界门槛与晋阶 | 选择准备、挑战或再探索；资格与失败原因可见 | 阶段成长有可感知结果 | 满30仍一阶、经验积存、通过后解锁与补发升级按规则结算 | 阶级体系与挑战脱节 |
| 天赋、技能与配置 | 少量协同/互斥配置；显示应用条件与预期效果 | 让不同探索目标改变准备与操作 | 营地应用成立，战斗中编辑不应用，生命比例/资源/冷却不重置 | 构筑不能形成真实选择 |
| 存档与重试 | 撤离、失败、回收或重开；明确进度保留与损失 | 允许持续沙盒投入并承担合理风险 | 完整退出再启动、失败后恢复、坏档恢复 | 长期培养与风险判断无法可信成立 |

死亡/失败规则仍需规格决策。建议保留公共世界进度、已培养装备与经历，针对本次未存入营地的资源设计可解释损失和回收机会；晋阶失败允许补给后再次挑战。其损失量、回收条件与重试耗时须试玩确认，不可自行承诺永久死亡或惩罚强度。

## 5. 双端与手柄操作建议

游戏规则只读取命名动作和瞄准意图，设备绑定由输入配置管理。以下是待原型验证的初始布局，不是已经实现的操作。

| 动作 | Windows 键鼠 | 横屏手机触屏 | 手柄 |

| 通用技能 | 初轮建议只装配1个主动通用技能，后续按需要扩展 | 1个技能按钮；避免首轮密集按钮挤压战场 | 另一肩键 |

首轮按钮建议为主攻击、闪避、防御、武器动作、1个通用技能，再加上下文交互。此数量是为了检验拇指可达性与战斗决策空间，不是最终技能数量。若防御与闪避作用重复或手机负担过大，应先调整动作职责与布局，再决定功能范围；不能悄悄删除用户要求的输入形式。

瞄准辅助应优先目标角度、距离和可见性，锁定变化要可见；辅助强度、作用范围与目标切换条件配置化，不能自动代替锚点策略。离散动作缓冲、按住/切换、摇杆死区与取消手势须各自确定条件，并用真实设备验证；未测量前不宣称某个毫秒窗口或像素尺寸最佳。

镜头旋转不应成为过关必需：首个区域在默认锁定视角下也应读懂敌人、道路与出口。高墙遮挡、跟随滞后、缩放上限、战斗特效和 UI 覆盖需在不同宽高比与实际角色显示尺寸中检查。自由/固定视角均保留跟随与复位；相机手势与攻击拖动必须分别消费输入，取消/打开菜单后释放所有残留动作。

## 6. 最小可玩与垂直切片建议范围

### 最小可玩原型：验证核心因果

沿用用户范围：一个营地、一段完整一阶探索、一场晋阶挑战、同一把闪电枪的一阶三目标连锁到二阶导电锚点成长。原型可用明确标记的基础几何体；真实采集、补给消费、敌人状态、战斗奖励、升级门槛、撤离、失败、保存、退出恢复必须执行规则，不能通过假菜单或自动发奖替代。

建议只制作足以形成对照的内容：安全绕行与风险路线；近战追击与远程/分散威胁两种敌人职责；稀疏/密集敌人两种遭遇；一个功能性营地设施与一种补给制作；挑战后可回访的空间。实际数量是验证建议，待纳入规格才成为实施范围。XP 与资源曲线可迭代，但完整流程必须通过真实经验与挑战达到阶段门槛；测试预置状态只用于规则边界或局部对照，不能冒充完整晋阶流程证据。

原型退出条件建议：能从开始完成两种路线中的一种、战斗、撤离/失败、回营、资源消费、满级挑战资格、挑战成功、二阶锚点使用、退出恢复；核心规则自动测试通过；Windows 完整流程与输入实际执行；真人观察核心假设。Android 输入可先做技术准备，原生真机任务保持独立待验收。未获真人样本时，原型“体验通过”保持未完成。

### 垂直切片：验证代表品质及制作方法

在相同循环上完成一个原创代表区域、一个基础可用角色样本、两种职责清楚的敌人及晋阶遭遇、闪电枪两阶段外观/动作/效果、必要营地交互与装备 UI、暂停/设置/存档。角色样本先建立制作基准；切片完整验收建议包含2角色以验证共享成长、专属及切换，其范围以D-005/TASK-026冻结为准。制作范围沿既有关键流程闭合，不能用增加区域数量代替修订当前体验。

切片需加入融合与扩槽的实际合法性、成本与培养反馈验证：候选不足、锁定后剩余预算不足、互斥、重复、阶级不符、品质不符、材料不足都须有明确结果。建议无法产生合法成品时在确认前阻止操作并说明原因，不收费、不吞装备；此规则尚需纳入规格。稀有机制保留、阶段参数成长、4/5槽预算与主装备经历需有可复现证据。

技术/生产退出条件：实际源资产与许可追踪、技术检查、导入与实机展示、动作事件和反馈同步、画质档差异可读、记录的 Windows 性能、存档故障恢复、已确认Android设备的安装与完整流程/热稳定性测试。玩家体验、工程与生产流程三者的门槛分别记录，缺一项时不进入扩大内容生产的已验收状态。

### 当前范围与后续候选

- 当前推进：离线单人关键循环、共享规则的三设备输入设计、Windows 验证、移动预算与操作准备、原创代表资产生产路径。
- 后续独立评估：2–4人合作、跨境界战斗适配、交易/赠送、跨平台组队、账号/云存档、2角色样本以外的更多角色/境界/分支/技能珠宝、完整建造规模。
- 正式版体量、商业模式、价格、预算和期限没有足够事实依据，本研究不生成承诺值。

## 7. 原创视听生产路径与可比较品质基准

### 原创设计建议

环境主题建议围绕“失效城市设施被幸存者重新利用，异变能量让旧空间产生新功能”。可用结构明确的维修构架、模块化防洪建筑、回收管线与移动导电设备形成自身形状语言。冷色环境用于废弃与危险，受控暖光用于生活与可交互设施；二阶锚点用形状、动作与能量节奏体现新能力。此方向尚待风格样本与实机可读性验收，不因参考图相似或AI生成而自动具有原创性。

| 阶段 | 计划路径 | 必须检查的实际产物/证据 |
|---|---|---|
| 风格与资产简报 | 明确尺度、镜头距离、角色显示尺寸、形状/色彩/材质规则；概念图与简单场景样本先比较 | 在游戏实际视角下的角色、敌人、设施和道路可读性；原创差异与本项目用途 |
| 概念/纹理/UI | 能力核实后优先本地 ComfyUI 工作流；文字与交互布局由引擎原生 UI 承担 | 模型/节点许可、输入参考、参数、种子、输出、采用版本；纹理接缝、压缩与图集透明边缘 |
| 核心模型/动画 | Blender 分步建模、UV、材质、骨骼、主要动作、碰撞代理、LOD；保留源工程 | 比例、原点/朝向、拓扑/法线、UV、变形、持物与穿插；实际导入游戏后检查 |
| 场景/材质/VFX | 已核实引擎与渲染器中组织模块化建筑、光照、湿地面、雨雾与电流反馈 | 正常游玩/镜头移动/战斗时的遮挡与稳定性；Windows/Android实际成本，不只离线渲染 |
| 原创声音/音乐 | 自录或合成机械、电弧、脚步、雨/排水与界面反馈；本地生成只按已安装可运行模型能力采用 | 源音频、制作工程/工作流、许可；接缝、重复感、视听事件时序、手机扬声器/耳机试听 |
| 集成与批量生产 | 代表资产在实际显示尺寸通过后再扩展同一视觉/声音家族 | 资产清单、来源、采用文件、版本、技术报告、游戏内截图/录像、设备成本与批准状态 |

Godot/Blender/ComfyUI 的具体当前能力与许可，以父任务工具核查为准。本研究没有调用资产生成，不宣称已产生模型、动画、声音或最终美术。

声音建议采用 Master、Music、SFX、Ambience、UI 总线与独立设置；关键危险/命中优先于雨声和音乐，限制重复声音并发，脚步按地表区分；电弧“起始/连接/失联/锚点成功”用可区别的声音并配视觉反馈。氛围与战斗音乐可使用少量可复用层，首先检查转换和暂停恢复，而非在首轮扩大曲目量。声音来源、商用与源文件再分发权限分别核查；制作成功不代替耳机与手机扬声器试听。

### 将“整体优于参考”转为可执行比较

现有图片可提供空间、材质和光色基准，视频可提供同一环境在不同视角下的参考。拍屏视频清晰度受限，不能直接对比源渲染帧时间、声效或原生手机性能。因此建议把“优于参考”保留为最终质量目标，并分项设置可检查的条件；本轮未达到或证明该目标。

| 维度 | 切片检查方法 | 初步合格条件建议 |
|---|---|---|
| 空间与环境细节 | 与附件相近斜俯视构图，固定相机截图+路径巡游；分别检查近中远层次 | 轮廓/道具/地面细节有一致尺度；道路、出口与主要目标可辨；无明显接缝、浮空、碰撞穿透或堆砌遮挡 |
| 建模与动作 | 游戏原生显示尺寸检查角色/敌人、设施及武器两阶段；近景检查重点资产 | 玩家身份、敌人职责、持物与二阶新能力可读；比例、法线、变形和接触时序无发布阻断缺陷 |
| 材质与积水 | 同一固定点静止、移动镜头与战斗；PC/手机画质各录一组 | 湿/干、金属/混凝土/植被有可信差异；反射不持续闪跳，水不遮住危险提示，降级后仍保留湿度表达 |
| 光照与雾雨 | 同一场景、可重现天气状态；明暗位置分别操作与观察 | 冷暖焦点有职责；暗部仍能读道路/轮廓；雨雾不掩盖威胁；亮度/闪烁可调并经设备检查 |
| 镜头与战斗可读性 | 默认锁定、旋转、缩放、复位、墙后移动与密集遭遇全过程 | 默认视角可通关；遮挡处理可靠；拖动/手势不误触攻击；切换模式不跳转丢失角色；必要提示不依赖单一颜色 |
| 整体偏好与运行成本 | 对比注明来源/画质/分辨率/拍屏限制；提供无剪辑可游玩录像、目标设备帧时间与盲评记录 | 技术门槛先通过；评审逐项写观察与原因，再作整体判断。未取得真实设备与非制作方评价前，“整体优于”保持待验收 |

不能仅以截图更锐利、分辨率更高、生成器返回成功或自评打分宣布质量目标通过。确立参考构图、展示分辨率、动态片段、允许差异和评审参与者后，将最终判断条件写入 Spec Kit 验收条款。

## 8. 真人试玩与继续/调整/停止条件建议

首次建议邀请至少5名与目标匹配的生存/构筑玩家进行探索性观察，初轮用5名分母；其中包含手机熟悉玩家和PC熟悉玩家。建议4/5独立完成循环并解释一次选择、3/5自发再试，方案未冻结，样本用于找卡点不代表市场统计。参与者、来源、构建SHA、设备、已有经验、任务情境、提示、观察、原话与录像分别记录。先给中性的目标，不教“正确路线”或引导玩家说好玩。

| 假设 | 可观察条件 | 记录方法 | 调整触发 |
|---|---|---|---|
| 能理解出营目标与回营价值 | 能描述要找什么、为何准备补给/空间，独立找到出口 | 首次理解时间、求助次数、误读内容、实际路径 | 多次出发却不知道资源用途，优先修任务/提示/制作关系 |
| 风险选择有实际意义 | 在两条路线/继续或撤离之间作选择，能说明危险与收益，结果反映选择 | 选择、补给、背包、受击与结算前后状态 | 总选唯一优解或选择没有后果，调整路线/收益/资源约束 |
| 电枪成长改变操作 | 一阶主动寻找密集敌人；二阶使用锚点连接分散敌人，理解布置成本与失联原因 | 锚点布置位置、首目标、失败、同遭遇两阶段对照 | 只感到伤害变高/新按钮无用，修锚点规则与遭遇布局 |
| 危险与失败公平可读 | 能在伤害前看见/听见预备，死亡后能指出原因，并知道下一次要改变什么 | 错误类型、受伤前画面、失败解释、重试耗时 | 不可见攻击、输入误触或未知惩罚，暂停扩大内容并修反馈 |
| 手机与PC操作成立 | 完成相同关键动作，菜单不漏入攻击，旋转/缩放/取消不残留动作 | 误触、摇杆丢失、瞄准失误、遮挡、手部舒适度 | 核心操作依赖三指或持续遮挡主要威胁，修布局与输入策略 |
| 愿意主动再远征 | 完成/失败后主动选择再出发、换路线/配置，并说明原因 | 是否自发重玩、理由、放弃点，不只满意度分数 | 只能靠研究者要求继续，检查循环目标与重试成本 |

**继续**：关键操作与规则成立，玩家能解释结果、展现不同有意义选择，核心假设得到真实观察支持，且没有未关闭的推进/存档严重缺陷。
**调整**：目标、反馈、操作或资源取舍失败时，先根据观察修订并用同情境对比；不得增加内容掩盖问题。
**停止扩大生产**：关键假设在连续修订后仍不成立，或核心双端玩法/预算没有可行证据时，保留结果并重新评估方案。次数与阈值在试玩任务确认，不能凭一次主观印象自动下结论。

本轮没有招募、访谈、真人试玩、游戏实机或Android真机测试。所有此类任务应保持未完成。

## 9. 实施前少量关键决策与规则澄清

父任务统一汇总问题，设计侧不重复向用户提问。建议优先确认：

1. **设备/资源条件**：Android具体设备与可用手柄、人力/预算/外部服务和里程碑约束。缺少时可推进PC与设计，不可填写虚构设备、期限或成本。
2. **战斗与失败门槛**：首轮主动通用技能数量、防御/闪避职责、死亡/挑战失败损失与回收规则；这是探索节奏和手机可操作性的主要变量。
3. **规则解释**：三目标连锁是否包含首目标（建议总命中最多3个敌人）；锁定后候选/预算不足如何阻止非法融合；阶级进阶后普通词条如何成长；共享天赋总点数是否可为各角色独立配置（建议独立配置、共享已获得总量且不重复领取）；这些必须在编码前进入权威规格。

世界阶级、装备预算、概率、经验、奖励、技能与输入参数应集中配置并可复现。实现阶段以具体验收条件推进；高低阶联机适配、交易与云存档依合作评估单独立项，不因双端平台默认开启。
