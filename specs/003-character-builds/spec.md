# Feature Specification: 角色、天赋与流派预设

**Feature Branch**: `codex/003-character-builds`（已实际激活）

**Created**: 2026-10-13

**Status**: 自主冻结并进入实施；规划激活已验证，其余实现与验收仍未完成。

**Input**: 用户授权持续完成《另一个世界》，自主调研和决策。承接阶段001的REQ-015至018、AC-015至018及阶段002真实单人基础；D-014采用“各角色按世界共享已获总量独立配置”的解释。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用两种身份完成同一世界的远征 (Priority: P1)

玩家在营地选择盗窃者或疗愈者。两者沿用同一世界等级、境界与公共库存；盗窃者从自己的真实怪物金币获得5%额外收益，疗愈者可以独立自疗。角色切换保留当前生命比例、剩余资源和冷却，不会创造补给。

**Why this priority**: 身份差异必须落实到真实收益和可操作能力，后续流派才有价值。

**Independent Test**: 从已有合法进度切换两角色，受伤后自疗，返回营地切换并重载；实际击杀与成功/失败远征对照金币及余数。测试夹具只证明局部边界，实际游玩另列证据。

**Acceptance Scenarios**:

1. **Given** 受伤40/100、体力30，**When** 合法切换角色，**Then** 新生命保留40%比例，体力至多30，资源数量和共享冷却不变。
2. **Given** 每只怪物基础金币2、已入库盗窃余数0，**When** 盗窃者累计成功带回10次该怪物奖励，**Then** 基础金币20、额外金币1、余数0；任务币不参与该计算。
3. **Given** 疗愈者受伤且技能就绪，**When** 使用自疗，**Then** 支付规定体力并恢复生命，随后切角色、换预设、返回标题或重启均不能刷新恢复冷却。
4. **Given** 活动遭遇、短暂脱战或尚未重置，**When** 请求切换，**Then** 明确拒绝，生命、库存、装备和冷却无部分变化。

### User Story 2 - 查看和试配自己的天赋 (Priority: P1)

玩家随时查看和编辑天赋草稿，两角色各按同一世界的已获总量分配；编辑不影响当前战斗，合法应用仅在营地且遭遇结束发生。属性变化有可见前后对照。

**Why this priority**: 获得天赋点需要转化为可理解、可验证的构筑取舍。

**Independent Test**: 在世界总量10时，两角色可各配置10点；任一11点配置拒绝应用。修改草稿不影响真实攻击/生命上限，合法应用与撤销后的比例及冷却守恒。

**Acceptance Scenarios**:

1. **Given** 世界已获10点，**When** 盗窃者与疗愈者分别应用10点，**Then** 世界仍只有10点，不要求两角色配置之和不超过10，也不重复发点。
2. **Given** 远征中编辑攻击天赋，**When** 未回营应用，**Then** 当前攻击伤害与已生效配置不变。
3. **Given** 任一天赋超单节点上限、总点数超预算或非法名称，**When** 应用，**Then** 整项拒绝并说明原因；原配置不变。

### User Story 3 - 保存三套流派并装配通用技能 (Priority: P1)

每角色恰有三套可命名预设，保存天赋、两个通用技能槽和装备实例引用。角色专属技能由身份决定，不能转移。预设应用前显示资格、成本为零的重配性质以及装备引用失效原因。

**Why this priority**: 保存取舍与快速比较支持持续培养，不能以快捷切换绕过战斗状态。

**Independent Test**: 两角色共六槽分别保存/编辑/覆盖/重载；同一库存装备可被多个非活动配置引用但全世界只有一名活动角色。材料装备融合后，旧引用显示失效、拒应用，原主装备经历保持。

**Acceptance Scenarios**:

1. **Given** 两套不同天赋/技能/装备配置，**When** 分别保存并重载，**Then** 各槽内容独立，编辑一槽不修改其他槽或已生效配置。
2. **Given** 预设引用装备后来作为融合材料消耗，**When** 查看并尝试应用，**Then** 显示缺失实例与原因并拒绝；不自动替换、不复活材料、不复制其经历。
3. **Given** 未达二阶或同技能占两槽，**When** 应用相应配置，**Then** 拒绝；已合法解锁的通用技能可供两角色装配。

### User Story 4 - 在合法阈值下获得共鸣并可靠恢复 (Priority: P2)

满足天赋分支点数和装备/技能阶段后，共鸣才生效；界面逐条说明尚缺条件。旧进度更新后保留等级、资源、原装备身份与经历，新增系统有确定的默认配置。

**Why this priority**: 共鸣改变站位或防护取舍，同时不能借组合获得未解锁高阶能力。

**Independent Test**: 在阈值前一/等于阈值、装备阶级前后、技能未装配/已装配分别检查效果；旧版本进度迁移两次结果相同；非法/未来格式保留有效旧槽和原内存状态。

**Acceptance Scenarios**:

1. **Given** 二阶电枪和足够游走分支点数，**When** 应用配置，**Then** 导电锚点连接范围按限定增量变化，总连锁目标数仍遵循既有阶段上限。
2. **Given** 防护分支达到阈值但未装配屏障，**When** 查看共鸣，**Then** 明确未激活，不产生额外屏障。
3. **Given** 旧进度只有原电枪与既有库存，**When** 更新并恢复，**Then** 不补金币/材料/治疗、不克隆装备，旧世界和经历保留；新增预设与冷却初始状态有迁移说明。

### Edge Cases

- 0点、阈值前一、最大59点、负数/小数/未知节点/单节点超限；草稿超预算与生效配置分别校验。
- 合法死亡检查点HP0纯迁移不补给；继续旅程显式按失败回营恢复35%，清buff保CD及已入库进度，不静默clamp复活（ADR-036）。
- 每次写入均在进程内仓储锁下守卫全部有效代次，已启动会话也不覆盖未来领域/偏好。保存失败保留dirty与会话，退出/标题转换需重试成功；退出可明确放弃未保存内容，取消恢复原菜单/暂停状态（ADR-038/CR-003-03）。
- 同一装备在多角色非活动配置出现、切换至缺失装备、当前武器作材料、非活动引用材料被消耗。
- 最大生命升降、体力上限截断、生命为0、共享技能调换槽位、卸装再装、暂停/失焦/标题/重启。
- 盗窃余数跨多次远征、任务奖励、不含金币的守卫、失败与中断、重复击杀/重复结算。
- 旧存档无新字段、缺失一部分新字段、未来领域版本、非法角色/技能/装备引用、坏槽、迁移失败。
- 共鸣满足点数但不满足武器或技能阶段；多共鸣不能改变既有境界、链目标上限或专属身份。

## Requirements *(mandatory)*

### Functional Requirements

- **REQ-201**（自主冻结）: 提供盗窃者与疗愈者，两者共享世界等级/境界/总天赋和公共库存，各自保存身份与独立配置；全世界仅一名活动角色。 → AC-201
- **REQ-202**（用户源要求、数值细节自主冻结）: 盗窃者5%仅计算本人怪物基础金币，整数奖励与余数准确，任务币/其他来源币不加成，重复事件及失败/中断不可重复入库。 → AC-202
- **REQ-203**（用户源要求、数值细节自主冻结）: 疗愈者自疗可单人使用；同类恢复共享持续冷却，切角色/预设/重载不刷新；使用需受伤、支付资源并遵守存活/暂停条件。 → AC-203
- **REQ-204**（D-014自主冻结）: 每角色独立按世界已获总天赋量配置，分别校验预算与节点上限；随时查看编辑草稿，不影响战斗生效配置；应用只在营地+遭遇结束。 → AC-204
- **REQ-205**（用户源要求）: 每角色恰三套独立预设，保存天赋/技能装配/装备实例；查看编辑不改生效，应用重验场所、预算、技能及装备资格。 → AC-205
- **REQ-206**（自主冻结）: 两个通用技能槽支持选择已解锁的不同技能；专属自疗只能由疗愈者发动，不经技能装配或装备转移；冷却以技能身份共享而非槽位。 → AC-206
- **REQ-207**（用户源要求、一至二阶范围自主冻结）: 游走导体、蓄雷护体按明确分支点数和装备/技能阶段共同激活，未满足说明原因；不授予三阶专属能力、额外链目标或无代价完整分支。 → AC-207
- **REQ-208**（用户源要求）: 应用预设/角色保留生命比例、体力余量和持续冷却，不自动补生命/体力/金币/材料；属性重算不能累积漂移，装备身份和已发生经历保持。 → AC-208
- **REQ-209**（自主冻结）: 库存实例允许多非活动配置引用；当前活动武器禁止作为材料。消耗其他引用材料前显示受影响预设，消耗后保留引用并显示失效、拒应用，不静默重绑或克隆装备。 → AC-209
- **REQ-210**（用户源要求）: 新角色/构筑/冷却和金币余数可靠保存；进度领域版本升至2而存档容器格式不变，旧领域1幂等迁移不补资源、不复制装备；旧客户端与当前客户端均拒绝各自未来领域并阻写，非法生效配置拒绝覆盖，陈旧非活动引用可恢复为可见失效状态。 → AC-210

### Non-functional Requirements

- **NFR-201**: 规则、运行状态、输入/场景、界面与持久化分离；统一数值与校验，应用采用完整预检后一次提交、失败无副作用，数据快照相互独立。 → AC-211
- **NFR-202**: 风险单元/真实输入流程/存档故障/历史回归分别有非零测试和证据；禁止用造等级、伤害或资源代替游玩验收，缺真人/设备仍单列。 → AC-212
- **NFR-203**: 键鼠、手柄、触控意图及提示一致，长菜单和技能状态可访问，减少闪烁保持有效；角色/VFX原创源与采用记录存在，商业品质和Android/手柄真人验收保持独立。 → AC-213

### Key Entities *(include if feature involves data)*

- 世界天赋总量：只源自现有世界成长，角色不能增发。
- 角色档案：身份、生效配置、独立草稿、三预设及非活动引用有效性。
- 构筑配置：九天赋节点分配、两通用槽、真实武器实例引用；共鸣由条件导出。
- 共享战斗状态：生命/体力及上限、技能身份冷却、恢复家族冷却、仍在持续的屏障/聚焦效果。
- 怪币余数：已入库余数与当次远征余数分开，和战利品一起确认或丢弃。
- 持久化领域版本：新系统候选、旧进度迁移来源、结构与应用资格的独立检查。

## Assumptions

用户授权自主收敛，角色、节点数和技能数值是可追踪制作决策，后续变更需同步规格和测试。先使用已验证的一至二阶世界与电枪，两个身份从本功能的新档可选；迁移也建立两个档案，均引用现有原装备而非各送一把。

三阶电枪、第二个人挑战、雷网/绯红分支、断链聚能高阶共鸣与珠宝进入视觉品质门槛之后的后继玩法阶段，作为完整产品依赖；用户将004调整为原创视觉样板，不在本功能放空按钮、虚构记录或未实现接口。合作另评估；没有外部付费、人力/日期承诺，设备和真人结论继续遵循宪章。
