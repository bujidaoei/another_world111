# Feature Specification: 原创视觉品质样板

**Feature Branch**: `codex/004-visual-quality-slice`
**Created**: 2026-10-13
**Status**: 制定与研究；视觉品质未验收。
**Input**: 用户否决当前简陋粗糙demo，要求先达到参考视频的画风、建模精细程度和完成度甚至超越，再继续后续开发；随后明确角色、建筑、布局从0到1原创，不要求模型一致。承接001 REQ-027/AC-027及002/003开放视觉门槛。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 进入可信的原创雨庭街区 (Priority: P1)

玩家在真实营地与雨庭看见完整街区包围、层叠建筑、尺度不同的铺装、排水与植被；主轮廓、构造、局部细节形成层次，金属、石材、织物与植被各有材料语言，湿地/暖光/接触连续。

**Why this priority**: 用户把画风与完成度作为新增玩法前置。
**Independent Test**: 在实际Main营地、中央、两边角和自由旋转5组取景对照参考风格；观察实际输入行走时材料和接地。

**Acceptance Scenarios**:
1. **Given** 真实可玩街区，**When** 移动与旋转镜头，**Then** 无大片裸背景/悬空边界/重复粗网格主导。
2. **Given** 同光照的五种材料，**When** 查看干湿过渡与移动画面，**Then** 类别与尺度可辨，无接缝/拉伸/纹理游移，细节有功能用途。

### User Story 2 - 看懂原创角色的动作与能力 (Priority: P1)

两身份用独立原创造型、装甲/装备/关节与材质表达职责。行走、转向、攻击、护盾、自疗、受击和敌人预备具备重心/接地/清楚起止。

**Independent Test**: 两角色近景和玩法尺度下真实输入10秒以上连续未暂停动作，检查轮廓、脚步、持枪、效果与真实规则同步。

**Acceptance Scenarios**:
1. **Given** 同镜头光照下的两角色，**When** 切换、行走和攻击，**Then** 职责轮廓可区分，无穿透/漂移/持续滑脚。
2. **Given** 技能成功或拒绝，**When** 实际输入施放，**Then** 仅真实成功产生对应动作/VFX/声音，弱闪烁模式仍可读。

### User Story 3 - 稳定游玩完整画面 (Priority: P1)

HUD、菜单和互动融入美术，优先生存/危险/目标；精修表现仍能战斗、采集、回营、保存恢复，实际渲染错误和导出启动故障收敛。

**Independent Test**: 固定原生Main与对应生产包真实流程、日志、长菜单、可比性能；设备/真人各自记录。

**Acceptance Scenarios**:
1. **Given** 精修场景，**When** 完成真实输入闭环，**Then** 资源/冷却/存档守恒，Native/Script/资源/生命周期错误0。
2. **Given** HUD与长菜单，**When** 缩放和操作，**Then** 不遮角色/主要危险、中文不裁切、状态真实更新。

### Edge Cases

相机靠墙/旋转/缩放/遮挡；材质/贴花/水/石缝交界；两角色和场景多次重建；蒙皮/动画/粒子owner退休；失焦/暂停/失败保存/退出；弱闪烁语义；资源缺失拒绝而非粗占位替代；低清拍屏不能证明纹理/原程序性能；Android、手柄、真人缺事实独立待验。

## Requirements *(mandatory)*

### Functional Requirements

- **REQ-301**（用户明确）: 对齐参考画风、材料/光照氛围、细节与完成度；角色、建筑、道具、布局与品牌原创。 → AC-301
- **REQ-302**（用户标准、自主量化）: 真实可玩街区在营地/中央/四边形成完整空间承接和大中小层次，无大片裸背景与粗网格主导。 → AC-302
- **REQ-303**（自主制作）: 石材/涂漆金属/裸金属/织物/植被可辨，干湿/磨损/锈蚀/墙根/排水按功能分布，保留真实源与UV/纹理。 → AC-303
- **REQ-304**（用户完成度、自主造型）: 两角色原创分层造型和完整现有动作，在玩法距离职责清晰、关节/武器/脚部可靠。 → AC-304
- **REQ-305**（自主制作）: 雨、水、灯、命中、屏障、自疗和敌人预备有真实动态及事件同步，弱闪烁模式语义完整。 → AC-305
- **REQ-306**（自主制作）: HUD/菜单/互动有统一层级，屏幕服务角色/危险/目标，中文与长菜单可访问。 → AC-306
- **REQ-307**（原工程要求）: 收敛BUG-112-01与003导出smoke超时；保留复现/根因/修复/同完整流程证据，不吞错误或改视角冒充解决。 → AC-307

### Non-functional Requirements

- **NFR-301**: 指定Godot/Blender/本地ComfyUI MCP、GdUnit4、Playwright与两套Skills按职责实际生产/研究/验证；依赖/源/许可齐全，无未批准收费任务。 → AC-308
- **NFR-302**: 当前Windows生产1080p60预算有帧时/峰值内存/负载证据；Android/实体手柄/真人按事实分别验收。 → AC-309
- **NFR-303**: 可比镜头/分辨率/尺度下完整对照与10维独立审查，全项≥2且平均≥2.3，并且主要可比较维度不得低于参考；通用分数达线不替代参考完成度。缺动态/性能不算通过，逐项比较参考。 → AC-310
- **NFR-304**: 原角色/成长/库存/奖励/冷却/输入/存档回归；不为视觉验收伪造业务状态或替代真实输入。 → AC-311

### Key Entities

视觉目标合同；原创资产与源/采用记录；材料/湿度区；镜头与动作捕获集合；固定运行证据；视觉缺陷；品质审查。

## Assumptions

先做真实营地/雨庭代表样板，实际验完再扩生产。现有两机械身份可重设计分层/比例/装备/材料，保持业务身份和存档；具体造型自主决策。三阶等完整需求保留到视觉门槛之后。低清视频无法证明原程序功能/性能。预算、人力/期限与设备/真人不虚构；用户授权自主研究制作，不重复询问。
