# 《另一个世界》Constitution

## Core Principles

### I. Spec Kit 是唯一规范入口

立项、需求、研究、设计、任务、编码、调试、测试、验收、变更与进度必须通过本仓库 Spec Kit 工件追踪。
采用 REQ、NFR、AC、TASK、TEST、BUG、ADR 稳定编号。每次实现前明确规格与验收，完成后同步实际状态。
关联研究、资产记录和证据不得形成冲突的第二套需求来源。

### II. 玩法与真实证据优先

使用真实输入、规则、状态、奖励和持久化。不得以假业务、空接口、测试替身、截图或工具成功替代实际功能。
实现、已测试、待验收、已验收分别记录；任务规定的证据与验收条件全部满足后才勾选。
真人、设备、长期运行各有独立门槛；没有真人证据不得宣称好玩，没有 Android 真机不得宣称双端验收通过。

### III. 可维护的工程边界

核心成长、奖励、装备及状态规则可独立测试；输入、场景、UI、音频、存档和平台分别适配。
集中校验配置，类型和生命周期符合固定版本，信号与异步资源有明确释放路径。
不得用临时补丁、无生命周期兼容代码、未经核实的 API、硬编码密钥/服务地址或注释替代实现。
复杂架构必须说明当前价值和成本；离线阶段不引入账号、后端、商城、云存档或分析 SDK。

### IV. 原创品质与双端约束

批量生产前定义代表性角色、环境、动作、VFX、UI、声音样本及实际游戏内验收标准。
保留原创源工程、采用版本、生成/修改记录和第三方许可；商用与 GitHub 源资产再分发分别核查。
基础几何体只能标记为原型。比较参考需相近构图、运动、实际可玩状态与性能记录，不能先宣称胜出。
触控、键鼠、手柄通过共享规则适配；设备未就绪不降低验收标准。

### V. 可靠存档、测试与交付

存档不得覆盖唯一有效版本；定义版本、校验、备份、迁移、错误提示、恢复和最大进度损失。
核心规则边界、输入消费、完整流程、故障恢复及缺陷回归有真实测试记录；失败、零测试或跳过不能报通过。
性能记录设备、构建、场景、采样方法、分位帧时间、长帧、峰值内存和稳定性暴露量。
依赖固定版本/提交，CI最小权限；发布排除开发工具和私密材料；安全认证、小步提交、核对远端 SHA。

## 范围与授权

本轮交付阶段 0。已确认优先离线单人验证，再评估合作；Windows 使用当前电脑，Android 真机后续接入。
未确认的设备档位、预算、人力、工期、首发规模和合作方案记录为决策门槛，不以默认值冒充同意。
无需重复请求已授权常规动作。敏感源需求不得原样复制；使用已有安全认证，不保存聊天中的密码。

## 开发流程与质量门槛

使用实际安装的 Codex Spec Kit skills，按 constitution → specify → clarify → plan → checklist → tasks → analyze 推進；
implement 只作用于当前授权阶段，之后收敛检查和状态同步。
恢复时先读当前规格、计划、任务、风险与最近证据。需求质量检查和实现测试报告分开。
高风险缺陷按复现、证据、根因、修复、原问题验证、相关回归关闭；未达门槛保持开放。

## Governance

用户指令优先。规则解释、平台、系统、内容、质量或成本改变时，先记录变更原因、影响及决策，
再依次更新规格、计划、ADR、任务、里程碑并验证。不得悄悄降低标准。
宪章版本使用语义版本：原则不兼容变更升主版本，新增原则升次版本，澄清升补丁版本。
所有交付必须核对工件和真实产物；通过静态关联检查不代表完成语义审查或游戏验收。
