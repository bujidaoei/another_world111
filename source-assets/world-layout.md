# 庭院场景布局与审查记录

关联 Spec Kit：阶段 1 原型 `specs/002-singleplayer-prototype/`，资产与场景任务 TASK-110、TASK-111、TASK-112。此记录只描述真实交付与证据，不自行勾选最终游戏或视觉验收。

## 可调用接口

`AWWorldBuilder.build(region: String) -> bool` 要求新的空节点；支持 `rain_court` 和 `conduit_yard`。失败返回 false，`configuration_errors: PackedStringArray` 给出配置/导入/材料诊断，不生成替代资产。主流程应拒绝继续启动失败的世界。

保留公共 `camp_position`、`bench_position`、`exit_position`、`gate_position`、`resource_positions`、`pickup_nodes`。各区 `lighting_profile` 是完整复制的字典，环境拥有者在首次建造和换区后应用：

| 参数 | 雨庭 | 导体工场 |
| --- | --- | --- |
| ambient_color / energy | 53676b / .30 | 405963 / .26 |
| sun_color / energy | eee0c1 / 1.15 | c9dbdc / 1.05 |
| fog_color / density | 537076 / .006 | 456b77 / .007 |
| water_color | 324447 | 24434b |
| ground_tint / roughness | 919a95 / .55 | 7d8e95 / .42 |

环境源文件由主场景拥有者管理，本模块只提供配置与三盏无阴影实际区域灯。两区同时有机械布置变化：雨庭四件散落物资箱、两侧各一个储液罐与暖色侧灯；导体工场东侧双储液罐/双长管廊、额外通风设备和双青色继电器，保留相同玩法锚点。

运行配置统一为 `game/config/world_assets.json`。源生成脚本读取两个原创清单；游戏不读取任何 source-assets 文件。布局是作者数据，可单独改配置并重新验证。每个模型的 `bounds_m` 是全部真实顶点转换后的 Godot Y-up 局部边界，不能把高空天线 AABB 当作玩家碰撞盒。

## 物理与相机

泵站位于 `(-10,0,-14)` / `(11,0,-14)`，绕 Y 轴 PI 后正面朝向庭院；7.26×3.60×4.80m 实体盒不允许进入屋内。四个资源位置仍为 `(-11,0,-1)`、`(11,0,-6)`、`(-8,0,-10)`、`(2,0,-12)`，实测 0.38m 半径/1.7m 玩家胶囊在资源点无障碍覆盖。

维护棚位于 `(-8,0,12)`、yaw=-PI/2，正面朝向营地中央。模型内部中央可以走，不能用整棚 AABB 封死空棚。维护台仍在 `(-3,0,12)`，台前 `(−3,0,13.5)` 保持胶囊无障碍。

四周有连续实体边界，南侧低墙与北侧闭合门板在实际物理 shape query 中阻挡。可见墙/建筑实例与碰撞体分离，后者通过 `occlusion_visual` WeakRef 关联视觉，视觉根节点的 `camera_occluders` 组让相机按实例淡出。地面、资源拾取、Label、人物不加入组；共享 PBR 图集不能被相机直接修改。

连续物理面 Y=0，底座可见网格顶=-.136m，2m 模块最高维修片贴齐0，主要石板面约低8–14mm。水面独立位于 .011–.014m；后续若观察到悬浮/穿插，必须同时审查脚部和水面，不能只抬一个节点掩盖问题。

排水格栅没有单独行走碰撞，必须嵌入地面；放置偏移由实际 .105m 最高边界计算，使表面只高于0约1mm，避免装饰网格高出10cm而脚穿过。该关系已加入导入网格高度专项检查。

## 已观察问题与验证边界

初轮 `artifacts/prototype-camp-first.png` 只支持发现问题：大棕色前景棚遮挡、扁平灰面、线形边界、稀疏大箱子、矩形水面花纹。Modal 覆盖主体，不能据此评分战斗角色可读性。第二族解决机械轮廓、地面几何、边界结构与后街层次；当前没有足够证据称作最终商业美术或优于用户参考。

地面首轮接入实机暴露不透明基础网格盖住低于物理面的石板，已改为 collider-only + 下置可见底座，并补上高度门禁。headless MultiMesh 读回是 Dummy identity，因此实际渲染证据必须来自正常 GPU 进程。23件导入网格边界、6项世界配置/物理测试已真实通过，完整移动/战斗/交互输入、遮挡与性能仍由主流程复测。

下一批实际渲染审查需覆盖：1280×720 无 modal 营地；同相机中央朝北；雨庭与导体工场同位置对照；玩家接近维护棚、侧墙、泵站时渐隐前后；中央/格栅/水边脚部；全屏和窄窗口 HUD。画面审查关注主角/敌人优先级、1秒可读功能标记、石板与水面接触、明暗冷暖分层、管线过密/干扰、远街尺度与遮挡恢复。Android、真人与最终参考品质仍待真实验收。
